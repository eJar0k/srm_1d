## Implementation notes / deviations from the spec text

1. **`floor_min_raw_P` "no clamp" value is a finite sentinel (1e300), not +inf.**
   Spec says "start at +inf". The kernels are compiled with `fastmath=True`,
   which sets the no-infs flag; comparing against an inf operand is undefined
   there. 1e300 is a neutral element for a running min and is never reachable
   by a real pressure. Callers gate on `n_floor_cells > 0`; the Python summary
   converts "never" to NaN as specified. Pinned by a test.
2. **Energy and min-raw-P reach the summary via two scalars returned from
   `_run_time_loop`** (`floor_energy_total`, `floor_min_raw_P_global`). The spec
   lists only two per-step arrays (cells, mass) and is silent on how the other
   two summary values get out of the compiled loop. Activations, steps, mass
   and first-time are derived in Python from the per-step arrays. First-time
   uses the step-START time convention of the `time` history.
3. **`piso_step` code is unchanged.** The spec says to update it; it slices
   `out[0:4]` so the longer tuple needs no code change. Docstring updated.
4. Because the clamp precedes the state carry, the `min_pressure` history can
   never read < 1000 Pa; it pins at exactly 1000.0 when the floor is active.
   Noted in DEVNOTES and asserted in a test.

### Finding: B0 at rtol 0 is compile-state dependent; T3 is not the cause

Reported before the coordinator's note and consistent with it. Reproduced on
UNMODIFIED HEAD (a `git archive HEAD srm_1d` copy in `C:/tmp/sv_t3/pre`, run
with a copy of the gate script pointed at that package):
- HEAD, cache-loaded: PASS (identical), rtol 0.
- HEAD, fresh compile: FAIL at rtol 0 with EXACTLY the same digits as the T3
  fresh run above (11.472831280605048 / 8.22246581335032 / 8.42348927652059 /
  4.366702806070182 / 4.913378178011641 / 6.143912554793208 /
  2.3816074267208065), n_steps identical.
So a fresh in-process JIT compile and a cache-loaded run of the SAME source give
different floats at ~1e-16..1e-9 (fastmath compile-state noise). The mechanism
is not identified (hypothesis only: whole-module re-optimisation/inlining
differs between the in-process compile and the cached object code). It also
means any "bit-identical" claim only holds comparing like with like.
