## Config semantics (important, one deviation fixed mid-run)
Config = burn_update_interval / geometry_update_interval / cfl_target. Default intervals resolve to 21 steps
(106 cells, N//5) on all three motors. `geometry_update_interval=None` FOLLOWS an explicit
`burn_update_interval` (T5), so the spec row "1 / default / 0.3" must pass the resolved default geometry (21)
explicitly; the probe does this (takes it from the motor's base row). My first launch passed None, so its
`b1` rows were really b1g1; I killed that process (only my own PID), discarded the `b1` rows
(kept aside in `C:/tmp/sv_t7/results_invalid_b1.jsonl`, not committed), patched the probe and re-ran them.
The `b1g1` rows from the first launch were valid and were kept.

## Metric definitions
As in `docs/v0_7_4/probes/mp_cap_crossmotor.py` (Chunc plateau = median P_head over [0.4,0.9] s; BALLSstick
peak in t<0.3, trough = min over (t_pk,1.2), mid = P nearest t=1.03; pk/trough, pk/mid). `min_P_Pa` = global min of
the `min_pressure` history (Pa); "minraw P" = `summary['pressure_floor_min_raw_P']` (NaN = floor never fired).
`fill_mach` = max(`max_mach`[t < t_peak]) (the whole pre-peak window, which for these motors includes the first
ignition fill; it is NOT Codex's per-grid fill Mach 1.987 etc. -- different definition/igniter bookkeeping,
not reconciled here; only relative changes matter). Peak/plateau/trough/mid in MPa.

## Findings (numbers only)
1. **No validation metric moves > 1% in any config on any motor.** Largest: BALLSstick peak +0.342% /
   pk/trough +0.342% (b1g1 at cfl 0.15), pk/mid +0.335%; Chunc peak +0.180%, ratio +0.179%, plateau <= +0.002%;
   Hasegawa A peak <= 0.001%. Flagged list (>1% on Chunc peak/plateau/ratio, BALLSstick pk/trough, pk/mid, peak,
   Hasegawa peak): **empty**. (t_peak moves -0.6..-1.05% on Chunc/BALLSstick; t_peak is not in the flagged
   validation set. BALLSstick b1g1cfl015 t_peak -1.050% is the largest.)
2. **Burn-rate refresh cadence is the driver; geometry cadence is not.** b1 and b1g1 agree to ~0.01% on every
   motor/metric; g1 changes peak <= 0.007% but min P -9.36% on Chunc (0.00% BALLSstick/Hasegawa).
3. **Min P (fill transient, t ~ 2.4-4.9 ms):** every-step burn raises global min P by +14.4% (Chunc), +6.0%
   (BALLSstick), +12.0% (Hasegawa) -- reproduces T5 (+14.44/+14.45%). CFL 0.15 alone raises it +57.5% / +10.0% /
   +45.5%; b1g1 + CFL 0.15 +56.8% / +12.6% / +57.0%. Min P is NOT converged in either axis (CFL halving moves it
   far more than refresh cadence on Chunc and Hasegawa). Time of min P shifts only 2.479 -> 2.440 ms (Chunc).
4. **Fill Mach (pre-peak max Mach):** falls with finer time resolution: Chunc 3.944 -> 3.725 (b1, -5.5%) /
   3.382 (cfl 0.15, -14.2%) / 3.320 (b1g1cfl015, -15.8%); BALLSstick 2.847 -> 2.761 / 2.749 / 2.731 (-3.0 /
   -3.5 / -4.1%); Hasegawa 3.580 -> 3.437 / 3.097 / 3.024 (-4.0 / -13.5 / -15.5%). Still unconverged.
5. **Pressure floor: 0 activations in all 18 rows** (100-cell grids; raw P NaN everywhere), so the
   `min_pressure` series here is a true minimum.
6. **Max refresh gap at default:** 143.83 us (Chunc), 168.29 us (BALLSstick), 297.77 us (Hasegawa A); every-step
   rows equal the max single dt (7.11 / 8.91 / 14.69 us). Codex's 29.84 us not reproduced (as T5).
7. **Plateau-window stationarity** (linear-fit slope as %/s of window mean; std/mean) -- identical across
   configs to the quoted digits:
   - Chunc [0.4,0.9] s: slope **+11.53 %/s**, std/mean **1.68%** (mean 8.241 MPa, n ~ 2.6e5 steps). Over the
     0.5 s window that is ~ +5.8% drift. Not stationary (consistent with Codex's failed 0.6-1.8 s test).
   - BALLSstick [0.9,1.2] s (window I chose around the t=1.03 "mid" sample; the spec defines no BALLSstick
     window): slope **+34.5 %/s**, std/mean **2.99%** (mean 4.952 MPa). Not stationary (~ +10% over 0.3 s).
   - Hasegawa A: only peak/t_peak are validation metrics; no plateau window defined/measured.
   The windows are time-sampled per step, so n differs with CFL; the slope/std are independent of it. The
   "plateau"/"mid" values are therefore window-position dependent, but their cadence sensitivity is <= 0.007%.
8. **Cost:** steps/s ~ 46-55k (burn default) vs ~10-15k (every-step burn), i.e. ~4x slower
   (Chunc 35 s -> 48-50 s at the same step count when run alone vs under load -- see wall note); CFL 0.15 doubles
   steps (+99.96..99.995%).
