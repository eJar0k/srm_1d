## Gap definition
Both kinds refresh at step 0 (t=0). Gap = simulated time between consecutive
refresh events = Σdt of the steps between them (step-start `t`). The open
interval after the last refresh is not counted.

## Correction (PA / R1, 2026-10-05): Codex's "29.84 µs" IS reproducible
The "not reproduced" statements above are superseded. Codex's 29.84 µs is a
different statistic from the max refresh gap measured here: it is the
**per-ignition delay to the next burn-rate refresh** (for each ignited cell,
`time[next refresh step] - ignition_time`, next = `(ignition_step // interval + 1) * interval`),
not the largest time between consecutive refreshes. R1 reproduced 2.984e-5 s on
Codex's 100-cell MTV startup. PA ported it as
`srm_1d.tools.ignition_diagnostics.ignition_refresh_delays(result)`; on canonical
Chunc (100 cells, 50 ms, interval 21) it gives max 2.8748e-5 s, median 9.947e-6 s
over 100 ignitions, while `max_burn_refresh_gap_s` stays 1.4383e-4 s. The two
statistics are consistent, not in conflict. See `worklog/PA.md`.
