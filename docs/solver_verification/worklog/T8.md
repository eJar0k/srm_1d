### Why Codex's "current BPNV" numbers (1.987/2.200/2.311) differ from 3.10/3.94/4.94
I added `--knobs codex` (Codex `baseline_configs.json` Chunc knobs: roughness 35e-6, kappa 0.45, T_ign 900, k_solid 0.4,
P_cutoff 50 kPa; CFL 0.3, t_max 0.05) and ran their three igniters at 50/100/200 cells:

| igniter (Codex knobs) | Mach 3 ms (50/100/200) | Codex published | pre-peak max (t of max ms) |
|---|---|---|---|
| library BPNV | 1.9875 / 2.2002 / 2.3105 | 1.987 / 2.200 / 2.311 | 2.927 (3.81) / 3.692 (3.69) / 4.667 (3.34) |
| legacy BPNV | 3.2702 / 4.8132 / 11.6867 | 3.271 / 4.821 / 11.722 | same as 3 ms (1.88 / 1.55 / 1.34 ms) |
| MTV | 0.4481 / 0.4976 / 0.4794 | 0.448 / 0.498 / 0.479 | 2.614 (6.29) / 3.209 (6.94) / 4.111 (8.23) |

The discrepancy is the config, acting through the metric window: with Codex's T_ign 900 K / k_solid 0.4 ignition is later,
and for library BPNV and MTV the Mach excursion falls at 3.3-8.2 ms, outside their `t <= 3 ms` window, so their number is
the smaller in-window value of the earlier fill. The canonical config (T_ign 756) puts the maximum at 1.7-2.9 ms, inside
the window. The metric (max over cell-centred |Mach|) is the same array in both trees; cell-vs-face is not a factor. The
reviewer's 3.94 @ 2.48 ms (library) and 4.81 @ 1.38 ms (legacy), 100 cells, t <= 20 ms are reproduced (3.9416 @ 2.483,
4.8056 @ 1.378). The legacy igniter has no window artifact (max at 1.2-1.9 ms in both configs).
