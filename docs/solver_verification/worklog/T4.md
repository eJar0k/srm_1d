### (a) Tab-boundary parity vs openMotor — 81 tests

* An openMotor `Propellant` is built from a dict in openMotor's own schema
  (3 tabs with a gap: [0.1, 2], [2, 6], [8, 15] MPa; distinct a/n:
  (3.0e-5, 0.40), (5.5e-5, 0.32), (1.2e-4, 0.20)). The srm_1d propellant is
  `convert_propellant(om_prop.getProperties())` — the adapter's own conversion
  applied to openMotor's serialisation (the dict a `.ric` stores), so units
  are the adapter's, not the test's. The fixture asserts openMotor actually
  holds the intended values (openMotor's `FloatProperty.setValue` SILENTLY
  ignores out-of-range input, which would make a test vacuous).
* Run for three tab-list orderings (ascending, descending, shuffled
  (1,2,0)): the closest-boundary tie-break ("first tab wins an exact tie") is
  order dependent in both implementations, so parity must hold in each.
* 25 named pressures per ordering: every tab min and max exactly (6), each
  tab's midpoint (3), shared boundary 2 MPa, in-gap 7 / 6.9 / 7.1 MPa,
  below-all 0.05 MPa, above-all 20 MPa, and the 1-ulp neighbours
  (`np.nextafter` both ways) of every distinct edge (0.1, 2, 6, 8, 15 MPa
  → 10). Plus a dense sweep of 2501 pressures in [0.01, 25] MPa per
  ordering, and a test pinning the semantics themselves (strict containment,
  closest-boundary fallback).
* Per pressure it asserts: `select_tab_idx` selects the tab whose (a, n) ==
  openMotor's `getCombustionProperties` (a, n) (exact float equality — the
  adapter passes a/n through unchanged); the Python-level
  `Propellant.select_tab` agrees (a, n, γ); `saint_robert_from_tabs(P)`
  equals openMotor's `getBurnRate(P)` (rel 1e-12).
* Result: **all pass; no divergence anywhere**, including the in-gap exact tie
  (7 MPa) and the shared boundary (2 MPa) in all three orderings. The task's
  expectation ("already matches") holds.
* Discriminating power (scratch, not committed): four deliberately wrong
  lookups were compared against openMotor on the same named-pressure list;
  each is caught (number of the 25 pressures that expose it, ascending /
  descending / shuffled): ties resolved last-wins 4/4/4 (e.g. gap-7 MPa,
  shared 2 MPa); min-distance-only 7/3/4; max-distance-only 3/7/6;
  nearest-tab-centre 2/6/5. (Note: strict `<` vs inclusive `<=` containment
  is behaviourally EQUIVALENT with this fallback in every ordering, so no
  test can — or needs to — tell them apart.)

## Deviations / interpretations (all minor; flagged for the reviewer)

1. "skip the module cleanly if unavailable": the openMotor-dependent part (a)
   skips via a module-scoped fixture (`pytest.skip` on `ImportError` from
   `_setup_openmotor_path`/`motorlib`); parts (b)–(d) do not need openMotor
   and still run. Narrower skip = strictly more coverage when the checkout is
   missing.
2. Total impulse: `run_from_ric` already returns `perf =
   compute_motor_performance(...)`; the test calls `compute_motor_performance`
   explicitly (as the spec names it) and asserts it equals `perf`'s value.
3. Extras beyond the spec (all additive, no semantics invented): three tab
   orderings; 1-ulp edge neighbours; dense sweep; Python-level
   `Propellant.select_tab` check; a registry-coverage guard
   (`_ALL_CODES == [0, 1, 2]` so a future erosive model must be added to
   (b)/(c) deliberately); two-tab-set parametrisation in (b); non-vacuity
   guards in (c) and (d); a `-s` printout of the per-mode deltas.
4. "Burn duration": the spec does not define it; both `perf['burn_time']`
   (5%-of-peak thrust window) and `summary['t_burn']` (simulated time at
   termination) are recorded; neither is asserted (spec says "record").
5. No xfail was needed: **no defect was exposed by any T4 test.**
