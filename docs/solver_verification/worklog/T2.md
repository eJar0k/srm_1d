## Open items / things the reviewer should know

- **Behaviour change at `r0 == 0` (consequence of the edit as specified):** a
  call with `P <= 0` and `Re_local >= 100` has `r0 = 0`, `F_lo = -ebf*h0 < 0`,
  `r_hi = 20*r0 = 0`, so `F_hi < 0` and the bracket widens to `ebf*h0`.
  OLD code returned `(0.0, 0.0)` (verified with a copy of HEAD
  `burn_rate.py`); NEW returns the pure-erosive root (e.g. P=0, Re=1e5,
  D=40 mm -> r_total = 1.329e-3 m/s; Re=1e7, D=2 mm -> 4.979 m/s). It is
  unreachable in the simulation (the post-PISO pressure is floored at 1e3 Pa,
  initial P is ambient, so `r0 > 0` whenever a cell is burning), and B0 is
  unaffected, but a direct caller passing `P <= 0` sees a change. A guard
  (`if r0 <= 0: return 0.0, 0.0` before the bracket check) would restore it;
  not added because the spec limits the code-0 edits to the two listed ones.
  Noted in the DEVNOTES entry.
- The clamp never bound in the three canonical motors (B0 trajectories are
  bit-identical to HEAD), consistent with Codex's "Chunc baseline unchanged".
- The `diagnostic_disable_erosive` path in `simulation.py` computes
  `r_normal = r_total - r_erosive`; that is still exactly `r0`
  (`r_erosive = r_total - r0`), so it is unaffected.
- The DEVNOTES entry is inserted at the TOP of the API Breaking Changes Log;
  T1 and T3 will likely insert at the same spot (trivial merge: keep all).
